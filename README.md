简体中文版lstprjct/IDM-Activation-Script — GBK 编码的批处理脚本，带有中文菜单，专为 Windows 用户设计，避免出现 CP936 控制台乱码。模式：[2]激活（推荐）、[1]冻结试用版、[3]重置[4]、[5]禁用/恢复 IDM 的自动更新检查。无需二进制补丁，自动备份注册表。完整详情：英文版 README 文件。

项目简介
IDM 激活脚本中文版（IDM Activation Script）是lstprjct/IDM-Activation-Script的简体中文维护分支：全中文菜单、GBK/CP936 控制台编码、一键输入，把 Internet Download Manager（IDM）的试用期冻结、即时注册信息激活、试用状态重置、关闭自动更新检查封装一个下面即用的批处理工具。不修改 IDM 程序文件，每次修改前自动备份，运行时只依赖 Windows自带组件（CMD / PowerShell / O），不安装、不下载任何第三方程序。

功能说明
怎么选？看你当前的状态：

没有领取 30 天试用期 / 想直接能用→ 选择[2] 激活（最常见，推荐）
已经领取并正在使用 30 天试用期（有 IDM 账号、点过“开始试用”）→ 选[1] 冻结激活（把当前试用期冻结住，不变成变量）
选择[2]激活后IDM仍提示“未注册”→改用[1]作为冷冻兜底
🌟激活（菜单[2]）[最常用]
功能：写入注册信息直接激活IDM，激活后即可正常使用
优点：最简单直接、立即可用，不需要账号、也不需要先领试用期
适用：未注册过试用期、或重新让 IDM 直接使用的用户
❄️激活（冻结）（菜单[1]）
功能：将IDM当前的30天实验期冻结住，不写入序列号
前提：你已经领取（激活）了 30 天试用期——冻结就是把这个试用期固定下来不适合过渡
优点：不会触发“假激进序列号”，在IDM 6.42+上最稳定、最顺利再弹注册窗口
适用：正在使用试用期的用户；或用[2]激活后仍被提示“未注册”时的兜底
🔄重置激活/试用期
功能：清除所有激活信息，恢复初始状态
用途：解决激活异常、更换激活方式
🔕禁用/恢复IDM更新提示（菜单[4]/，v1.4.0[5]新增）
功能：把菜单HKCU\Software\DownloadManager下的CheckUpdtVM设置为0（[5]改回1），关闭IDM的自动更新检查
效果：IDM不再反复弹“发现新版本/请更新”的提示窗；也不会自动升级到新版本导致激活失败
代价：停留在当前版本后，不再获得官方的修复与新功能；想更新时先选[5]恢复即可
说明：只修改这一个开关值，不写序列号、不动CLSID，与激活状态互不影响；执行前会先关闭正在运行的IDM让设置生效

技术细节
工作原理
以[1]冻结/[2]激活为例，实际执行顺序是：

前置检查+备份：确认IDMan.exe存在、能改变internetdownloadmanager.com（任一不满足即以退出码1退出，完成庭院），然后正在结束运行的IDM，把当前CLSID出口导出到%SystemRoot%\Temp
清理：删除HKCU\Software\DownloadManager下的注册信息与生物学计数值
恢复集成开关：把AdvIntDriverEnabled2写回1
锁定：扫描出 IDM 用于记录试用状态的 CLSID 键，取得语音后加 Deny ACL 锁地址（数量超过 20 个时改为直接删除）
写入注册信息：仅[2]激活模式执行，随机生成姓名/邮箱/序列号复位；[1]冻结模式跳过这一步，因此不会触发 IDM 的假序列号判定
验证+再锁定一次：调用IDM下载几张官网小图片确认下载功能正常，然后重新执行一次锁定
[3]重置是第1、2步+删除（取消锁定）CLSID键+第3步；[4]/[5]是独立分支，只改CheckUpdtVM一个值。

涉及的种植面积
只脚本脚本下面这些位置，不触及主机、防火墙、系统代理或任何IDM程序文件：

位置	用途
HKCU\Software\Classes\CLSID（64位系统走Wow6432Node\CLSID）	IDM 藏匿期跟踪信息的键；激活/冻结时取得线索后加 Deny ACL 锁住（识别出的键超过 20 个时才直接删除），重置时删除
HKU\<SID>\Software\Classes\CLSID	当HKCU与HKU\<SID>未同步时的等价路径
HKCU\Software\DownloadManager下的FName LName Email Serial scansk tvfrdt radxcnt LstCheck ptrk_scdt LastCheckQU	注册信息与统计计数；激活时重置，重置时删除
HKCU\Software\DownloadManager下的CheckUpdtVM	自动更新检查开关，仅[4]/[5]使用
HKLM\Software\Internet Download Manager下的AdvIntDriverEnabled2	IDM集成开关；清理排序键后重新写回1
HKLM\SOFTWARE\Internet Download Manager的InstallFolder、HKCU\Software\DownloadManager的ExePath	麻烦，用于定位IDM安装路径
退出码
无人值守 / 脚本化调用时可据此判断结果：

退出码	意义
0	正常完成（激活/暂停/重置/更新开关成功，或从菜单正常退出）
1	进入业务流程但未成功：未检测到IDM安装、传感器读取失败、IDM下载测试失败等
2	环境或参数错误：静默模式未带动作参数、系统版本不支持、缺少PowerShell、缺乏管理员权限、WMI失败、临时目录被阻止运行等
开始激活.cmd在自检发现问题且用户选择退出时返回1；已经是管理员时透传IAS.cmd的退出码。如果需要先弹UAC提权，激活流程会在新进程里运行，原窗口无法恢复退出码——这种情况请以管理员身份直接调用IAS.cmd。

导出备份
脚本会自动恢复植物到以下位置：

C:\Windows\Temp\_Backup_HKCU_CLSID_[时间戳].reg
C:\Windows\Temp\_Backup_HKU-[SID]_CLSID_[时间戳].reg
恢复方法：上面的.reg文件即可导入恢复。脚本每次跑完（含失败退出）都会把本次备份的文件名模式打印在末尾，照着C:\Windows\Temp去找即可。

注意：备份文件和运行日志不会自动清理，每一次就多一份（CLSID运行分支导出可能有几MB）。确认IDM工作正常后，可以自行删除C:\Windows\Temp下的_Backup_*_CLSID_*.reg与IAS-*.log。

编码说明
所有.cmd/.txt文件使用GBK（第936页）保存，并在运行时强制切换代码到相同代码页以保证中文显示。
在UTF-8环境下阅读源码，可使用iconv -f GBK -t UTF-8 IAS.cmd（或替换为其他文件名）或支持GBK的文本编辑器。
仓库通过.gitattributes修复.cmd/.txt为CRLF行尾，避免批量处理因LF换行损坏的校验错误。

v1.4.2 - 2026-07-28
上线前的稳定性补强，激活/暂停/重置/更新开关的逻辑线路未动。

修复日志文件名一直无效：生成文件名的几行究竟写在if (...)代码块内，CMD会在整块解析时一次性展开%_logstamp%，取不到上一行刚写入的值——所有静默运行的日志都叫IAS-%_logstamp%.log、追加进同一个文件。
/log=路径真正可用：文档一直写着这个方法，但参数解析只认不带路径的/log，按文档传输路径时日志会被静默写去别处。
开始激活.cmd提权时不再丢参数：以非管理员身份带参数运行（如/frz /silent）时，参数会被静静丢弃、提权后弹出是交互菜单。顺带修改了含的'目录路径导致提权语法错误的问题。
收尾会打印备份与日志位置：退出时基因组显示失败，不用再翻文档猜测路径。
新增发布包一致性守卫：CI会校验release/里的包与仓库逐字节一致、SHA256正确、版本号自洽——「修改了脚本忘记重新分配」之前没有任何征兆。
